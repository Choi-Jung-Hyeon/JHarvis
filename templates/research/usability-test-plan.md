# 사용성 테스트 계획

> AI 페르소나 워크스루로 화면만 보고 찾을 수 있는 문제는 먼저 고친다([persona-walkthrough.md](persona-walkthrough.md)). 워크스루는 이 테스트를 대신하지 않는다.

- **목적**: <사람만 말해 줄 수 있는 이해와 신뢰 확인>. 적은 인원이면 점수(SUS 평균)를 내지 않는다. 통계가 아니라 막히는 곳을 찾는 일이다.
- **어디서**: <운영 주소>, 참가자 본인 기기
- **방식**: 한 명씩 약 20분. 과제 <N>개 + 자유 탐색 3분 + 질문 5분. 진행자 1명(과제만 읽어 주고 돕지 않음) + 기록자 1명. 생각을 소리 내어 말하게 한다. 녹화는 화면만, 동의를 받은 경우에만.
- **계정**: 참가자 본인 계정. 끝나면 지울지는 참가자가 고른다(진행자가 대신 지우지 않는다).
- **일정**: 테스트 <날짜>, 기능 동결 <날짜>. 나온 문제를 고칠 시간을 동결 앞에 둔다.

| 참가자 | 배경 | 보는 것 |
|---|---|---|
| E1 | <전문가> | <표현이 실무 기준으로 맞는가> |
| A | <대상 사용자> | <처음 쓰는 사람이 혼자 끝까지 가는가> |

## 과제 (목표만 말하고 버튼 이름은 말하지 않는다)

| # | 참가자에게 읽어 주는 말 | 성공 기준 | 제한 시간 |
|---|---|---|---|
| 1 | "" | | |
| 2 | "" | | |

과제 사이에는 "이 화면에서 헷갈린 것이 있었나요?" 한 가지만 묻는다.

## 관찰 기록표 (참가자마다 한 장)

| 항목 | 성공(○/△/×) | 시간 | 막힌 곳(화면, 요소) | 참가자가 한 말(그대로) | 심각도(1~3) |
|---|---|---|---|---|---|
| 과제 1 | | | | | |
| 자유 탐색 | — | — | | | |

- ○ 혼자 성공, △ 힌트 한 번 후 성공, × 실패 또는 시간 초과
- 심각도 3 = 과제를 못 끝냄 또는 목적을 거꾸로 이해, 2 = 오래 헤맴, 1 = 잠깐 멈춤

## 사람에게만 묻는 질문 (답을 그대로 적는다)

1. **이해**: "방금 본 '<용어>'는 무슨 뜻이라고 생각하세요?"
2. **오해**: "이 화면이 <하지 않는 일>을 해 주는 것처럼 느껴졌나요? 어디서 그렇게 느꼈나요?"
3. **신뢰**: "얼마나 믿을 수 있을 것 같나요? 믿음을 더하거나 줄인 것은 무엇이었나요?"
4. **쓸모**: "언제, 무엇을 하는 데 쓰겠어요?"
5. **재방문**: "내일 또 열어 보고 싶나요? 왜 그런가요?"

## 정리와 수정

1. 문제마다 "몇 명이 겪었나 × 심각도"로 정렬한다. 전문가 지적과 대상 사용자의 막힘은 따로 표시한다.
2. 상위 문제를 이슈로 만들고 동결 전에 고친다. 문구와 배치 수정이 먼저, 새 기능은 동결 뒤로.

## 지키는 것

- 참가자 이름과 연락처는 레포에 적지 않는다(E1, A로만).
- 과제를 읽을 때 화면의 버튼과 메뉴 이름을 말하지 않는다.
- 사전 참가자로 진행 흐름을 먼저 점검한다.
