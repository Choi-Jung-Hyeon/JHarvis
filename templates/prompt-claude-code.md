# Claude Code 프롬프트 템플릿

채팅 Claude가 이 형식으로 쓰고, 사람은 그대로 붙여 넣습니다. AGENTS.md에 있는 규칙은 다시 쓰지 않습니다.

```
Goal
<한두 문장: 무엇을 바꾸고, 그래서 사용자나 팀에게 무엇이 달라지나>

Context
- 지금 상태: <관련 파일, 이슈·PR 번호, 실제 값이나 로그에서 확인한 사실>
- 확인된 것 / 추정인 것: <구분해서>
- 결정된 것: <사람이 이미 정한 방향, 바꾸지 말 것>

Constraints
- 하위 에이전트를 쓰지 않고, 끝나면 최종 보고를 한 번만 한다.
- <되돌리기 힘든 것 금지: 운영 데이터 삭제, 결제, 계정 설정, 남의 블록 대규모 변경 등>
- <범위 밖: 이번에 하지 않을 것>
- 무료 도구와 무료 한도 안에서만. 새 의존성은 MIT/Apache-2.0/BSD만.
- 운영 경로를 바꾸면 머지 전 /security-review, 정기 작업이면 dry_run 수동 실행.

할 일
1. <먼저 확인할 것: 로그, 실제 값, 기존 코드>
2. <구현 단위. PR 하나에 한 주제>
3. <테스트, 캡처(화면이면 390px와 1280px)>

보고 상태 구분: 계획만(실행 안 함) / 구현 보고(직접 확인 안 함) / 검증됨(테스트, CI, 화면으로 확인). 검증됨만 완료로 친다.

Done-when
- <검사 가능한 완료 기준: 테스트 통과, CI 초록, 특정 값 확인, 캡처 첨부>
- PR 링크와 바뀐 점 요약.
- 최종 보고는 /export 형식으로: 검토표(요청 항목별 완료 여부와 근거) → 놓친 것(못 한 것과 이유) → 다음 프롬프트(필요하면).
```
