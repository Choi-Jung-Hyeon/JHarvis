# DESIGN.md — 화면 규칙

> 한 화면에서 색이 있는 것은 <의미 있는 값(예: 상승과 하락)>과 주 버튼 하나가 전부다.

값(색, 글자 크기, 모서리, 그림자)의 원본은 `<globals.css @theme 또는 토큰 파일>`이다. 이 문서는 토큰이 표현하지 못하는 **판단 규칙**만 둔다.
우선순위: `AGENTS.md` > 이 문서 > 디자인 스킬. 톤은 절제된 쪽 — 강조하고 싶으면 색을 더하지 말고 주변을 덜어낸다.

## 기본 규칙

| 영역 | 규칙 |
|---|---|
| 정렬 | 모든 페이지 본문의 왼쪽 끝 = 헤더 로고의 왼쪽 끝. 컨테이너 폭은 하나. 읽는 페이지는 정렬은 두고 본문 폭만 좁힌다(최대 720px) |
| 화면 구간 | 1024px 이상 2단(8:4), 미만 1단. 1단 순서 = 2단의 왼쪽 → 오른쪽 |
| 글자 | 4단계만: 페이지 제목 28, 섹션 제목 20, 본문 16, 보조 13(흐린 색). 예외는 화면의 대표 수치 하나 |
| 간격 | 블록 안 8, 블록 사이 24, 섹션 사이 48 |
| 선 | 눌러서 들어가는 목록의 행 사이에만. 나머지는 간격으로 나눈다 |
| 상자 | 카드 단위로만. 카드 안 회색 상자, 칩 상자 금지 |
| 펼치기 | 기본은 다 보인다. 많을 때만 처음 3개 + "더 보기(N)". 펼침 안 펼침 금지. 계산 근거는 블록 맨 아래 접기 하나 |
| ⓘ | 용어 정의(두 문장 이하)만, 누르면 열림(키보드 Enter, Esc) |
| 구분 기호 | 가운데 점(·) 금지. 간격이나 쉼표 |
| 탐색 | 같은 목적지로 가는 길은 하나 |
| 개발 표시 | "검증 전" 같은 개발 상태 표시는 화면에서 뺀다. 예시 데이터 표시는 한 곳에만 |

## 읽는 순서
- 화면은 결론 → 나에게 해당하는 것 → 둘러볼 것.
- 2단이면 왼쪽이 "내 것", 오른쪽이 "둘러보기".
- 컨트롤은 그것이 바꾸는 내용의 제목 줄에. 행동 버튼은 읽는 흐름의 끝에.
- 앞으로 가는 주 버튼은 오른쪽 아래, 뒤로 가는 버튼은 왼쪽 아래. 라벨은 행동만("다음", "저장").

## 숫자와 말
- 숫자 하나는 네 단계로 읽힌다: 결론 한 문장 → 근거 숫자와 비교 기준 → 용어 정의(ⓘ) → 계산 근거(접기).
- 내부 점수는 본문에 쓰지 않고 단계나 말로. 계산 근거 안에서만 범위와 함께.
- 화면에 남기는 숫자는 단위가 있는 것만. 비교 기준과 기간, 출처를 붙인다.
- 쉬운 말 사전 한 파일 + 금지 표현 검사 테스트. 문장 끝 말투를 하나로(예: 해요체).
- 같은 대상은 한 이름.

## 기다림
- 300ms 안에 끝나면 표시 없음. 2~10초는 도는 표시와 한 줄. 10초 넘으면 % 막대, 남은 시간, 취소.
- 공용 컴포넌트 두 개만(도는 표시, 진행 막대). `prefers-reduced-motion`이면 글자만.
- 버튼은 누르는 즉시 눌린 상태로 중복 제출을 막는다.

## 모션
- 펼치기와 눌림 피드백에만, 150~200ms ease-out. 자주 반복되는 동작은 모션 없이.

## 하지 말 것
- 그라데이션, 글로우, 이모지 장식, 알약 배지 남발, 상자 안 상자, 스크롤 등장 애니메이션.
- 서체 추가(본문 서체 하나). 새 UI 라이브러리 추가.
- 없는 데이터를 그럴듯하게 만들기.

## 새 화면을 만들 때 점검
1. 브리프 한 단락 → 시안 2~3개 비교 → 구현.
2. 처음 온 사람 3문항: 첫 줄에 용도, 모든 숫자에 비교 기준과 출처, 다음 행동 하나.
3. 390px와 1280px 캡처로 자기 비판, 영향 큰 차이부터 고친다.
4. 입력칸: 이름표 = 무엇, placeholder = 형식, 오류 = 다음 행동, 선택 요소는 선택이라고.
5. 받은 피드백은 이 문서에 규칙 한 줄로 넣는다.
