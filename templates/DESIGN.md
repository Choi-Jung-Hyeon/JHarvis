# DESIGN.md — 화면 규칙

> 한 화면에서 색이 있는 것은 <의미 있는 값(예: 상승과 하락)>과 주 버튼 하나가 전부다.

값(색, 글자 크기, 모서리, 그림자)의 원본은 `<globals.css @theme 또는 토큰 파일>`이다. 이 문서는 토큰이 표현하지 못하는 **판단 규칙**만 둔다.
우선순위: `AGENTS.md` > 이 문서 > 디자인 스킬. 톤은 절제된 쪽 — 강조하고 싶으면 색을 더하지 말고 주변을 덜어낸다.

## 기본 규칙

| 영역 | 규칙 |
|---|---|
| 정렬 | 모든 페이지 본문의 왼쪽 끝 = 헤더 로고의 왼쪽 끝. 컨테이너 폭은 하나. 읽는 페이지는 정렬은 두고 본문 폭만 좁힌다(최대 720px) |
| 화면 구간 | 1024px 이상 2단(8:4), 미만 1단. 1단 순서 = 2단의 왼쪽 → 오른쪽 |
| 글자 | 4단계만: 페이지 제목 28, 섹션 제목 20, 본문 16, 보조 13(흐린 색). 예외는 화면의 대표 수치 하나 |
| 간격 | 블록 안 8, 블록 사이 24, 섹션 사이 48 |
| 선 | 눌러서 들어가는 목록의 행 사이에만. 나머지는 간격으로 나눈다 |
| 상자 | 카드 단위로만. 카드 안 회색 상자, 칩 상자 금지 |
| 펼치기 | 기본은 다 보인다. 많을 때만 처음 3개 + "더 보기(N)". 펼침 안 펼침 금지. 계산 근거는 블록 맨 아래 접기 하나 |
| ⓘ | 용어 정의(두 문장 이하)만, 누르면 열림(키보드 Enter, Esc). 꼭 필요한 정보를 툴팁에만 두지 않는다. ⓘ가 설명을 맡으면 같은 내용의 바깥 줄은 없앤다 |
| 구분 기호 | 가운데 점(·) 금지. 간격이나 쉼표 |
| 탐색 | 같은 목적지로 가는 길은 하나 |
| 개발 표시 | "검증 전" 같은 개발 상태 표시는 화면에서 뺀다. 예시 데이터 표시는 한 곳에만. 실제 데이터에는 아무 표시도 달지 않는다 |
| 열고 닫기 | 누를 때만. 올리기(hover)로 열리는 창 금지. 다시 누르기, 바깥 누르기, Esc로 닫힌다. 열린 창 안에 또 접지 않는다 |

## 색 역할표

색마다 쓰는 곳과 쓰지 않는 곳을 함께 적는다. 값은 토큰 파일에, 대비는 값 옆 주석에 적는다.

| 토큰 | 쓰는 곳 | 쓰지 않는 곳 |
|---|---|---|
| `brand` <값> | 기본 버튼, 링크, 현재 위치, 포커스 링 | 데이터, 차트 |
| `brand-accent` <값> | 선택 표시, 진행률 | 글자(대비가 모자라면) |
| `caution` <값> | 주의 점, 아이콘 | 글자 |
| `up` / `down` <값> | <의미 있는 두 방향> | 장식, 링크, 버튼 |
| `ink`, `body`, `muted` | 글자(제목, 본문, 보조) | |
| `ghost` | 비활성 면, 자리표시 | 글자 |
| `page`, `surface`, `line` | 페이지, 흰 면, 구분선 | |
| `danger` | 작업 실패 메시지 전용 | 주의, 위험도, 삭제 버튼(회색 '삭제') |

- 범주색은 두지 않는다. 순서 없는 범주는 색이 아니라 라벨과 위치로 구분한다.
- 사실(예: 기본 실선)은 무채색, 색은 신호에만.
- 색을 빼도 뜻이 전달돼야 한다. 방향에는 ▲▼나 부호, 범례는 점 + 단어. 색 이름을 글자로 쓰지 않는다.
- 모든 글자 색은 배경 위에서 4.5:1 이상, 아이콘과 테두리는 3:1 이상.
- 브랜드 색과 기관 색을 쓸 때 공식 색 값만 쓰고 로고, 심볼 이미지는 허락 없이 쓰지 않는다.

## 강조 계층 3단

| 단 | 무엇 | 모양 |
|---|---|---|
| 1단 | 판정 단어(그 카드의 결론) | semibold + 의미 색 |
| 2단 | 핵심 숫자(수준 값) | semibold + 본문색 |
| 3단 | 나머지 | 굵게 쓰지 않는다. 회색(본문, 보조) |

- 카드당 1단은 하나. 판정이 둘이면 하나만 1단, 나머지는 3단으로 내린다.
- 증감 숫자는 방향색 + ▲▼ 또는 부호. 표시 자릿수로 반올림해 0이면 본문색, 방향 기호 없음.
- 수준 값(가격, 비율)은 본문색이다. 축 눈금은 보조색.

## 글자와 간격 세부

- 굵기는 3단계(normal, medium, semibold). bold 이상과 임의 크기 금지. 숫자에 `tabular-nums`.
- 간격은 4px 배수만. 본문 행간 1.6, 제목 행간 1.3, 자간은 기본값.
- 한글은 `word-break: keep-all`, 제목 `text-wrap: balance`, 문단 `text-wrap: pretty`. 한 줄은 한글 약 40자 안팎.
- 같은 역할은 같은 글자. 나란히 놓인 행과 카드는 줄 높이가 어긋나지 않게 한다(필요하면 이름과 값을 두 줄로 고정).
- 글자를 키웠으면 한 화면 정보량을 줄인다. 섹션 제목은 한 줄, 부제와 eyebrow는 기본적으로 없다.

## 면과 그림자

- 테두리 대신 면으로 구분한다. 구분은 여백 → 안쪽 구분선 → 면 순서로 고른다.
- 그림자는 떠 있는 것(메뉴, 시트, 툴팁)에만. 가만히 있는 면에는 테두리도 그림자도 없다.
- 빈 상태는 한 문장 + 버튼 하나. 탭 모양은 하나만. 이모지 금지, 아이콘은 한 계열.

## 유리 층

콘텐츠 위에 떠서 움직이는 탐색 층에만 쓴다. 데이터는 늘 불투명한 면 위에 둔다(숫자 뒤로 다른 숫자가 비치면 읽기가 무너진다).

- 쓰는 곳: 상단 헤더, 팝오버. 카드, 목록, 차트, 모달 본문에는 쓰지 않는다. 떠 있는 유리는 두 겹을 넘지 않는다.
- 유리 위 글자도 4.5:1 이상. 글이 여러 줄이면 불투명도를 높인다(흰 90%).
- `prefers-reduced-transparency`, `prefers-contrast: more`, 흐림 미지원 브라우저는 불투명 면으로 바꾼다.

## 차트

- 차트 하나가 질문 하나에 답한다. 두 질문이면 차트를 나눈다.
- 격자는 최소(가로 기준선 하나 정도), 범례 대신 직접 라벨, 강조점 하나.
- 분포 그래프는 기준선을 늘 보이고, 묶은 끝 칸은 기준 숫자를 문장 안에 쓴다.
- 없는 미래를 그리지 않는다(모델이 예측하지 않는 값의 점선 곡선 금지).
- 차트 라이브러리에 넘기는 색만 토큰을 리터럴로 중복하고, 그 파일 맨 위에 이유를 적는다.

## 읽는 순서
- 화면은 결론 → 나에게 해당하는 것 → 둘러볼 것.
- 2단이면 왼쪽이 "내 것", 오른쪽이 "둘러보기".
- 컨트롤은 그것이 바꾸는 내용의 제목 줄에. 행동 버튼은 읽는 흐름의 끝에.
- 앞으로 가는 주 버튼은 오른쪽 아래, 뒤로 가는 버튼은 왼쪽 아래. 라벨은 행동만("다음", "저장").

## 숫자와 말
- 숫자 하나는 네 단계로 읽힌다: 결론 한 문장 → 근거 숫자와 비교 기준 → 용어 정의(ⓘ) → 계산 근거(접기).
- 값 아래에는 비교 기준 한 줄. 높아요, 낮아요, 비슷해요까지만 쓴다. 판정하는 말(싸다, 비싸다)은 쓰지 않는다. 계산할 수 없으면 이유를 쓴다.
- 라벨은 쉬운 이름 + 약어 괄호. 라벨 안에 긴 괄호 설명을 쓰지 않는다. 일상어에는 ⓘ를 달지 않는다.
- 극 이름과 단계 말은 결과가 아니라 행동으로 쓰고, 군더더기를 뺀다. 오른쪽이 축 이름의 '더' 쪽.
- 기준 시점과 출처는 `docs/research/source-display.md`를 따른다.
- 내부 점수는 본문에 쓰지 않고 단계나 말로. 계산 근거 안에서만 범위와 함께.
- 화면에 남기는 숫자는 단위가 있는 것만. 비교 기준과 기간, 출처를 붙인다.
- 쉬운 말 사전 한 파일 + 금지 표현 검사 테스트. 문장 끝 말투를 하나로(예: 해요체).
- 같은 대상은 한 이름. 표준 UI 용어를 먼저 고른다(삭제, 저장, 추가). 구어체와 귀여운 동사를 피한다.
- 보조 설명이 문장이면 마침표를 찍는다. 제목, 버튼, 라벨, 짧은 구는 마침표 없이.
- 같은 말을 두 번 쓰지 않는다. 면책 문구는 맨 아래 한 곳에.

## 기다림
- 300ms 안에 끝나면 표시 없음. 2~10초는 도는 표시와 한 줄. 10초 넘으면 % 막대, 남은 시간, 취소.
- 공용 컴포넌트 두 개만(도는 표시, 진행 막대). `prefers-reduced-motion`이면 글자만.
- 버튼은 누르는 즉시 눌린 상태로 중복 제출을 막는다.

## 모션
- 펼치기와 눌림 피드백에만, 150~200ms ease-out. 자주 반복되는 동작은 모션 없이.

## 하지 말 것
- 그라데이션, 글로우, 이모지 장식, 알약 배지 남발, 상자 안 상자, 스크롤 등장 애니메이션.
- 서체 추가(본문 서체 하나). 새 UI 라이브러리 추가.
- 없는 데이터를 그럴듯하게 만들기.

## 다크패턴 금지

사용자를 속이거나 압박해서 얻은 전환은 쓰지 않는다. 분류는 deceptive.design을 따른다. 화면을 낼 때 아래를 본다.

| 금지 | 뜻 | 대신 |
|---|---|---|
| 해지 방해, 진행 방해 | 가입은 쉽고 해지, 삭제는 어렵다 | 시작한 곳과 같은 깊이에서 끝낼 수 있게 한다 |
| 숨은 구독, 숨은 비용, 슬쩍 끼워 넣기 | 반복 결제나 추가 금액을 늦게 알리거나 숨긴다 | 누르기 전에 전체 금액과 주기를 보인다 |
| 미리 체크된 동의 | 사용자에게 불리한 기본값 | 기본값은 끔, 필수와 선택 동의를 나눈다 |
| 가짜 긴급, 가짜 희소, 가짜 평판 | 근거 없는 마감 시계, 재고, 후기, 활동 알림 | 실제 값만, 없으면 표시하지 않는다 |
| 죄책감 버튼 | 거절 문구로 부끄럽게 만든다 | 거절도 중립적인 행동 말로("나중에") |
| 속임 문구, 시각 방해 | 헷갈리는 이중 부정, 거절 버튼을 흐리게 숨김 | 두 선택지를 같은 수준으로 읽히게 한다 |
| 강제 행동, 반복 조르기 | 원치 않는 가입, 공유를 요구하거나 계속 띄운다 | 거절을 기억하고 다시 묻지 않는다 |
| 광고 위장, 비교 방해 | 광고를 콘텐츠처럼 보이게, 값을 비교하기 어렵게 만든다 | 광고는 광고라고 표시, 같은 단위로 보인다 |

결제, 구독, 금융 상품이 있으면 시작 전에 해당 법령과 가이드라인 원문을 확인한다.

## 보편 UX 체크리스트

1. 누르는 것은 44px 이상(문장 안 글자 링크 제외). 가능하면 e2e로 검사한다.
2. 글자 대비 4.5:1, 아이콘과 테두리 3:1 이상.
3. 주 버튼은 오른쪽, 취소와 뒤로는 왼쪽, 한 화면에 주 버튼 하나.
4. 되돌리기 어려운 행동 전에: 결과를 먼저 알리고, 저장 안 한 내용을 알리고, 확인 버튼에 실제 행동을 쓰고("확인" 대신 "프로젝트 삭제"), 되돌릴 방법을 남긴다.
5. 누르면 반응이 보인다(눌림, 로딩, 완료).
6. 오류 문구 = 무슨 일 + 어떻게 하면 되는지. 색만으로 오류를 알리지 않는다.
7. 같은 역할은 같은 컴포넌트, 새 화면은 기존 컴포넌트부터.
8. 선택지를 줄이고(힉), 누르기 쉽게 하고(피츠), 익숙한 방식을 쓰고(제이콥), 간격으로 관계를 보이고(근접), 중요한 하나만 강조한다(폰 레스토프).

이 목록과 위 규칙 밖의 것(배치, 정보 모양, 시각 실험)은 규칙으로 정하지 않는다. 시안 2~3개를 비교하고 피드백으로 정한다.

## 새 화면을 만들 때 점검
1. 브리프 한 단락 → 시안 2~3개 비교 → 구현.
2. 처음 온 사람 3문항: 첫 줄에 용도, 모든 숫자에 비교 기준과 출처, 다음 행동 하나.
3. 390px와 1280px 캡처로 자기 비판, 영향 큰 차이부터 고친다.
4. 입력칸: 이름표 = 무엇, placeholder = 형식, 오류 = 다음 행동, 선택 요소는 선택이라고.
5. 색이 있는 것이 정해 둔 것뿐인가, 색을 빼도 뜻이 전달되는가.
6. bold, 임의 크기, 새 색 값을 만들지 않았는가. 테두리로 나눴다면 면이나 여백으로 되는지 먼저 본다.
7. 받은 피드백은 이 문서에 규칙 한 줄로 넣는다.
