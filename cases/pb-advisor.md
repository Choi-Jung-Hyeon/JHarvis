# 사례: PB 어드바이저 대시보드(증권사 대학생 멤버십 프로젝트)

PB가 고객 상담에 쓰는 대시보드를 만든 프로젝트. 5인 팀, 2026-05 ~ 09, 매달 과제를 하나씩 쌓아 한 제품으로 합쳤습니다. 레포는 비공개라 PR 번호 대신 과제 차수로 적습니다.

## 무엇을 했나

| 차수 | 산출물 | 핵심 |
|---|---|---|
| 1차 | 상담 대시보드 | 저장소 협업 틀, 지표 계산 한 곳, 시드 강제 |
| 2차 | 리스크 리포트 엔진(LangGraph) | 결정론, LLM, 사람 계층 분리, 인용 검증 |
| 3차 | 폐쇄망 준법 사전확인 MCP 서버 | 4B급 로컬 모델 전제, 도구 4개 고정, 결정론 폴백 |
| 4차 | 신뢰 증명 레이어 | 라벨링 가이드, 채점관 캘리브레이션, 재현성 범위, 증거 묶음 |
| 5차 | 통합 허브(최종) | 통합 지도, 레포 통합, 시연 런북 |

## 스택
Next.js 대시보드, Python 백엔드, LangGraph, LangSmith, Chroma + BM25, Ollama(폐쇄망), FastMCP, Supabase, Vercel Hobby, Render Free.

## 졸업작품으로 옮긴 것

- 저장소 협업 세팅(main 룰셋, AGENTS.md와 CLAUDE.md, CONTRIBUTING, PR 템플릿, .gitignore)을 그대로 이식해 졸업작품 첫 PR로 썼다.
- 정량과 정성의 분리: 점수는 결정론, LLM은 설명에만.
- RAG는 필요한 곳에만. 첫 버전은 RAG 없이.
- 블록 결과를 마지막에 합치는 방식(late fusion).
- 시간 지평(단기와 장기)이 다른 블록은 먼저 맞춘다.
- 평가 함수 하나(SSOT)와 시드 고정을 최우선으로.
- 회피는 하드 제약(후보에서 제거), 선호와 성향은 소프트(가중치만).
- 회의록 양식(타임라인 표 + 안건별 핵심, 논의, 아이디어 후보 + Done/Todo/Discuss + 실시간 메모).
- AI 리뷰 봇은 무료인 것만 켜고, 개인 토큰을 쓰는 CI 액션은 넣지 않는다.

## 사고에서 나온 규칙

"언제"는 월별 과제 차수입니다.

| 사고나 발견 | 규칙 | 언제 |
|---|---|---|
| 병합된 정량 코드에 시드 없는 난수 폴백이 남아 있었음(재현성 주장의 구멍) | 시드 없는 난수 금지, 시드 강제 PR을 난수 추가 PR보다 먼저 머지 | 1차(대시보드) |
| 두 PR이 같은 지표 6종을 각자 구현해 화면 위치마다 값이 다를 수 있었음 | 지표 계산 함수 하나만 SSOT, 나머지는 import | 1차 |
| 파일명에 버전 숫자를 넣었더니 PR마다 다른 버전 파일을 참조 | 파일명에 버전을 넣지 않는다(버전은 git이 관리) | 1차 |
| 프론트 API 주소 환경변수가 비어 조용히 localhost로 폴백, 배포본이 저장을 못 함 | 필수 환경변수가 없으면 시작 실패, 배포 체크리스트에 변수 목록 | 1차 |
| 프론트가 이미 없어진 엔드포인트를 부르고, 살아 있는 엔드포인트는 안 부름 | 화면과 API 연결을 읽기 전용 스캔으로 정기 확인 | 1차 |
| 이미 머지된 기능(로그인)을 다시 만들 뻔함 | 실행 프롬프트 첫 칸은 정찰(선행 PR 머지 여부) | 1차 |
| 코드 품질 스캔 기능이 정식 출시와 함께 과금 전환 예정 | 과금 전환일을 예산표에 적고 그 전에 끔 | 1차 |
| 리뷰 도구 종료 공지의 날짜와 범위가 팀 안에서 어긋남 | 공지는 원문으로 확인, 범위가 애매하면 "미확정"으로 기록 | 1차 |
| 문서 교체 뒤에도 옛 청크가 인덱스에 남아 옛 수치를 인용할 위험 | 증분 추가 금지, 전체 재구축 + 신규 문자열 검색/구 문자열 부재 확인 | 2차(엔진) |
| 검증된 인용이 모두 한 주제 문서로만 쏠림 | 주제별 독립 검색 | 2차 |
| 그 수정이 다른 판정 축에서 오탐을 새로 만듦(회귀) | 한 축을 고치면 평가셋 전체를 다시 돌린다 | 2차 |
| 화면에 "검증 인용 0건"과 "품질 통과"가 동시에 뜸 | 상태 × 문구 표로 모순 점검 | 2차 |
| 재시도 상한을 바꿨는데 문서와 코드가 따로 놀 위험 | 상수는 설정 한 곳, 폴백 없음, 문서는 참조 | 2차, 4차 |
| 로컬 thinking 모델이 도구 호출에서 무한 루프 | 도구 호출에는 instruct 모델만 | 3차(MCP) |
| 유사도 임계값을 감으로 정했더니 무관 질의가 통과 | 두 그룹 실측 분리 폭으로 임계값 결정, 표로 남김 | 3차 |
| 해시 체인을 "위변조 불가"로 설명할 뻔함 | "수정, 삭제 탐지 가능"으로. 탐지와 방지를 구분 | 3차 |
| 한 과제 발표 자료에 다른 과제 꼬리말이 섞임 | 채팅과 산출물을 과제별로 분리, 제출 전 다른 프로젝트 이름 grep | 3차 |
| 채점관 프롬프트를 보강했더니 오탐이 두 배로 늘고 일치율이 떨어짐 | 라운드마다 한 가지만 바꾸고 같은 문제집으로 재측정, 하락도 기록 | 4차(증명) |
| 인용 검증이 미검증, 형식이 다른 인용을 통과시키던 사각지대 | 형식이 예상과 다르면 실패(fail-closed) | 4차 |
| 일부 사례에만 다중 호출 투표를 적용하면 지표가 섞임 | 관측 전용으로 분리, 공식 지표에 넣지 않음 | 4차 |
| 팀 공지에서 서로 다른 표본 수(관측용 n건 vs 제출용 m건)를 혼동 | 발표 숫자는 산출물을 직접 열어 확인한 것만 | 4차 |
| 통합하려던 두 시스템 사이 데이터 경로가 0개였음 | 통합 첫날 읽기 전용 통합 지도 | 5차(통합) |
| 같은 필드가 한쪽은 금액, 한쪽은 퍼센트인데 검증 통과 | 필드명에 단위, 단위 검사 테스트 | 5차 |
| 같은 VaR 함수의 신뢰수준 기본값이 시스템마다 다름, 응답 라벨은 고정 문자열 | 파라미터를 응답에 싣고 라벨은 파라미터에서 생성 | 5차 |
| 오래된 지점에서 분기해 add/add 충돌 | 항상 fetch 후 origin/main 기준 분기 | 5차 |
| 설정 없는 포매터가 무관한 파일을 대량 변경 | 프롬프트에 포매터 금지, self_check에 diff 통계 | 5차 |
| 시연 고정 데이터에 손으로 쓴 샤프 값이 공식 결과와 다름 | 파생값은 하드코딩하지 않고 공식으로 계산 | 5차 |
| 확정 뒤 입력 승인을 하면 확정이 풀려 출력이 다시 잠김 | 승인 순서를 전이표에 고정(입력 승인 → 확정) | 5차 |
| AI 에이전트 커밋 트레일러가 레포 CI 규칙에 걸려 실패 | 커밋 메시지 규칙을 AGENTS.md와 프롬프트 Constraints에 같이 | 5차 |
| 노션에 HTML 태그로 쓴 블록이 깨짐 | 노션 고유 문법만, 쓰기 뒤 다시 읽어 확인 | 1차 |
