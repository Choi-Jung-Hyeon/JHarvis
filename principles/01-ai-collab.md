# 01. AI와 일하는 규칙

## 역할

| 누가 | 맡는 일 | 하지 않는 일 |
|---|---|---|
| 사람 | 방향 결정, 되돌릴 수 없는 결정, 계정 로그인이 필요한 일, 최종 승인 | 반복 구현, 문서 초안 |
| 채팅 Claude | 계획, 위험 확인, 클코 프롬프트, 결과 검토, 문서와 팀 문구 초안, 사람이 할 일 가이드 | 코드 직접 실행(레포 권한이 없으면) |
| Claude Code(클코) | 구현, 테스트, PR, CI 확인, 머지(규칙 안에서), 조사 | 방향 바꾸기, 요청하지 않은 정리 |

## 진행 방식

- 꼭 물어야 하는 것(되돌릴 수 없고 어느 쪽도 가능한 결정)만 묻고 나머지는 과감하게 진행한다. 검증만 하다 진도가 안 나가는 것을 피한다.
- 응답 순서: 결론 → 자세한 설명 → 교통정리 표 → 넥스트 액션(번호 목록). 마지막 두 개는 빠뜨리지 않는다.
- 사람이 직접 해야 하는 일은 따라 할 수 있는 가이드로(어디를 열고, 무엇을 누르고, 무엇이 보이면 성공인지).
- 자연스러운 한국어. 번역투, 꾸밈말("다양한, 효과적인, 혁신적인")을 뺀다.
- 요청이 없어도 발표 주장, 팀 소통의 어긋남, 기술 오류는 먼저 짚는다.

## 클코 프롬프트

- 형식: Goal / Context / Constraints / Done-when. 템플릿은 [templates/prompt-claude-code.md](../templates/prompt-claude-code.md).
- 늘 붙이는 것: "하위 에이전트 없이 진행하고, 끝나면 최종 보고를 한 번만", "보고 형식은 검토표 → 놓친 것 → 다음 프롬프트".
- AGENTS.md에 있는 규칙은 다시 쓰지 않는다.
- 진단 작업은 "로그와 실제 값 확인 → 확인된 원인과 추정 원인 구분 → 수정" 순서.
- 운영 경로(정기 실행, 비밀키, 인증, DB 마이그레이션)를 바꾸면 머지 전 `/security-review`, 정기 작업이면 `dry_run` 수동 실행.
- 결과는 `/export` 파일이나 PR 링크로 채팅에 돌려준다.
- 실행 프롬프트는 정찰부터: 작업 트리, 분기 기준, 선행 PR 머지 여부를 보고하고 승인 뒤에 수정한다. 양식은 [XML판](../templates/prompt-claude-code-xml.md), [진단 전용](../templates/prompt-diagnosis.md).
- 진단과 수정을 한 프롬프트에 섞지 않는다. 못 본 것은 "미확인"으로 보고한다.
- 머지 대기 PR이 3개 이상이면 순서 표를 먼저 만든다. 규율을 까는 PR이 먼저.
- 킥오프에 "작업이 좁은 데로 매몰되면 알려 달라"를 넣는다. 그래도 진행하기로 한 사람의 결정은 따른다.

## 강제 장치 (부탁이 아니라)

| 위험 | 장치 |
|---|---|
| 비밀키 파일 수정 | `.claude/hooks/guard.py protect`(종료 코드 2로 차단, `.env.example`은 허용) |
| 깨진 코드 커밋 | `guard.py commit`(바뀐 영역의 빠른 검사만: 단위 테스트, ruff) |
| 계약 파일 단독 수정 | `.claude/settings.json`의 `permissions.ask`(예: `Edit(/schema/**)`) |
| CI 실패 상태로 머지 | GitHub Rulesets 필수 체크 + `gh pr checks <번호> --watch --fail-fast && gh pr merge <번호> --squash --delete-branch` |
| 요청 없는 대량 정리 | AGENTS.md 금지 사항: 브랜치, 파일은 이름을 하나씩 지정해서만 지운다(패턴 일괄 삭제 금지) |

## 리뷰

- 읽는 일은 기계로 옮기고, 사람은 만들지 말지, 위험한 코드, 구조, 근거 읽기, 결과 책임을 맡는다.
- 사람 승인 수는 위험도로 정하고 에이전트 승인은 세지 않는다. 표는 [templates/AGENTS.md](../templates/AGENTS.md).
- 리뷰와 수정이 3회를 넘으면 더 돌리지 않고 접근을 다시 본다.
- 완료 보고는 계획, 구현 보고, 검증됨을 구분한다. 검증됨만 완료로 친다.

## 토큰 아끼기

- 하위 에이전트, 병렬 에이전트, 상시 연결 MCP를 기본으로 쓰지 않는다(필요할 때만 일회성).
- 화면 확인은 Playwright 스크립트(스크린샷)를 먼저, MCP 브라우저 도구는 한두 번 눌러 볼 때만.
- 문서는 채팅 Claude가 텍스트로 쓰고 사람이 붙여 넣는 편이 싸다(노션 등).
- 긴 대화는 인수인계 문서로 끊는다([templates/handoff-chat.md](../templates/handoff-chat.md)).

## 개인 Claude Code 설정 (전역)

[claude/user/](../claude/user/README.md)에 실제 값과 새 PC에서 만드는 순서를 정리했다(공개 가능한 것만). 핵심:

- 모델은 `opus`, Opus 5.5 노력 수준 `medium`, 생각 켜기(`alwaysThinkingEnabled`), 자동 압축 켜기.
- 플러그인 3개: ponytail 5.3.2(코드 줄이기, 상태 표시줄), playwright(브라우저 확인, 필요할 때만 불러와 평소 토큰 부담 없음), vercel 0.50.0.
- 출력 스타일은 따로 지정하지 않는다(기본). 커스텀 명령도 두지 않고 내장 명령과 플러그인 명령을 쓴다.
- 허용 권한은 `gh api`, `git stash`, `git checkout`, `git push`만. main 보호는 Rulesets가 맡는다.
- 위험한 권한 건너뛰기(skip permissions)는 쓰지 않는다.
