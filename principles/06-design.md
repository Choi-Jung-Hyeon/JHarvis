# 06. 화면

자세한 규칙은 [templates/DESIGN.md](../templates/DESIGN.md)(새 프로젝트에 복사해 쓰는 판). 여기는 판단 기준만.

## 방향

- 절제된 톤(애플 웹처럼). 강조하고 싶으면 색을 더하지 말고 주변을 덜어낸다.
- 통일성이 최우선: 정렬, 글자 크기, 간격, 선, 상자, 펼치기, ⓘ 기준을 먼저 문서로 정하고 전 화면에 일괄 적용.
- AI 티 금지: 그라데이션, 글로우, 이모지, 알약 배지 남발, 상자 안 상자, 가운데 점(·) 구분.
- 규칙은 보편 원칙 위주로 꼭 필요한 것만. 나머지는 AI 시안을 보고 피드백하며 창의성을 보탠다.

## 작업 흐름

1. 브리프 한 단락(누가, 무엇을, 다음 행동) → 토큰 계획(색, 글자, 간격) → 시안 2~3개(Claude Design 또는 `?variant=` 비교).
2. 골라서 구현. 기존 화면의 배치, 탭, 구성은 최대한 유지하고 구조 변경은 먼저 보여 주고 받는다.
3. 390px와 1280px 스크린샷으로 자기 비판, 영향 큰 차이부터 수정(대비 같은 것은 숫자로).
4. 피드백은 규칙 한 줄로 바꿔 DESIGN.md에 넣는다.

## 화면 PR 통과 조건 (처음 온 사람 3문항)

1. 첫 줄에 이 화면의 용도가 보이나?
2. 모든 숫자에 비교 기준, 기간, 출처가 붙어 있나?
3. 다음 행동이 하나로 보이나?

## 사용자 언어

- 쉬운 말 사전 한 곳(용어, 정의, 읽는 법) + 금지 표현 자동 검사.
- 내부 점수는 화면 본문에 쓰지 않는다. 단계(5칸 막대)나 말로. 화면에 남기는 숫자는 단위가 있는 것만.
- 기다림: 300ms 안이면 표시 없음, 2~10초 도는 표시와 한 줄, 10초 넘으면 % 막대와 취소.
- 입력칸 4가지: 이름표 = 무엇, placeholder = 형식, 오류 = 다음 행동, 선택 요소는 선택이라고.
